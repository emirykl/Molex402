01The gap

Stellar already has working x402 settlement — the Apache-2.0 @x402/stellar package and a live facilitator both exist. What Stellar does not have is a Bazaar: a native discovery layer where an agent with no prior integration can find a paid service, understand its price, and pay for it. Stellar's own "Built on Stellar" directory currently lists zero discovery projects.

Molex402 fills that gap, and adds the piece every catalog leaves out: proof that the service you paid for is the service you actually received.

Discovery

Agents can't find Stellar services

Paid endpoints stay invisible. Without a catalog, every integration is hand-wired in advance — which defeats the point of an autonomous agent.

Trust

A listing is just a claim

Catalogs rank on self-reported metadata. An agent choosing a service on price alone has no signal about how that endpoint actually behaves under attack.

Delivery

Settlement isn't delivery

x402 proves money moved. It does not prove the paid work ran once, ran at all, or ran for that specific request. Retries and races can pay twice or deliver twice.

02What we're building

Five components, shipped open source under Apache-2.0, built on @x402/stellar rather than reimplementing verify and settle.

Core

Proof-Carrying Bazaar

Automatic cataloging from settled payments. /discovery/resources and /discovery/search over HTTP endpoints and MCP tools as first-class resource types, with natural-language search, structured filters and cursor pagination. Every listing carries a versioned security profile — last tested, which checks passed, and a link to the evidence.

Core

Facilitator

/supported, /verify and /settle on both testnet and pubnet, for the exact and upto schemes. Non-custodial, with fee sponsorship so agents never need XLM. Hosted, self-hosted and embedded library deployment modes.

Differentiator

MolexGuard

A framework-agnostic middleware for sellers. It holds the paid handler behind settlement finality and a durable state machine, so one payment produces at most one committed service effect — even under 1,000 concurrent replays of the same payment header.

Differentiator

MolexScope

A black-box attack suite that tests facilitators and resource servers from the outside: replay, header and cache confusion, verify/settle races, fee abuse and catalog poisoning. It turns "secure" from a claim in a document into a reproducible, signed test artifact.

Interface

Agent-facing MCP server

Search → inspect → pay → verify, split into deterministic tools an agent runtime can call. No tool ever asks for a private key; signing stays with the buyer's wallet.

Upstream

upto scheme for Stellar

A minimal, immutable Soroban settlement contract with no admin, no upgrade path and no custody — plus the spec and implementation contributed upstream to x402 and coordinated with the TSC.

03How a paid request works

The agent never has to trust the listing. It checks the security profile before paying, and verifies the delivered response against the payment afterwards.

  1. 01DiscoverSearch the Bazaar, filter on security profile
  2. 02BindSigned offer + request fingerprint
  3. 03ReservePessimistic lock on the payment
  4. 04VerifyAuth entry against requirements
  5. 05SettleStellar finality, fees sponsored
  6. 06ExecuteExactly one committed effect
  7. 07ProveSigned integrity evidence

Beaver402 is a two-party proof-of-intent system for agent payments over Stellar x402: a merchant signs a challenge describing the paid request, the buyer independently reconstructs it, and a Soroban smart account authorizes settlement only when every security-critical field agrees. It covers exactly the ground this RFP asks for — payment infrastructure, an MCP server, and a deployed Soroban contract.
